# Contributing to TFU FS25 mods

Start with the affected repository's issue form and SUPPORT.md. Discuss the reproduction and evidence before changing code.

Keep changes narrow. Preserve native mod identity, saved data, server/client responsibilities, ownership and administrator checks. Use verified FS25 code and documentation; do not assume FS22 behaviour applies. Retain existing authorship, asset credits and licence files.

Explain the actual cause, the change and the smallest relevant validation. Keep syntax/static checks separate from real in-game, dedicated-server and save/reload tests. Include unverified boundaries explicitly. Do not add unrelated features or reformat unrelated code.

Releases keep the four-part version convention. Attach the complete original-named FS25 ZIP to the release and record SHA-256. Do not publish a private TFU build, change a licence, merge a fix or release a new version without the owner's instruction.
